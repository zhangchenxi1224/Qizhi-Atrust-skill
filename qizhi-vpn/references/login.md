# 容器内登录与本机凭据

## 判断是否需要登录

先运行 `qizhi_vpn.py status`，用容器 HTTP 代理访问 `https://qz.sii.edu.cn/`，不跟随跳转。受保护入口可达说明 VPN 数据通路正常，302 跳转到 CAS 不代表网页用户已登录；网页会话按用户实际任务继续验证。容器 running、有 utun 接口或 aTrust 进程都不足以证明 VPN 登录成功。

如果无法访问，先查看 noVNC 中 aTrust 的可见登录状态，并排除代理、DNS、路由问题。不要因探测失败就反复提交账号密码。

## 正常认证路径

1. 使用当前会话允许的浏览器工具，先读取工具文档。打开本机登记的 noVNC 页面（默认 `http://127.0.0.1:16080/`），从本机私有部署 `.env` 读取 VNC_PASSWORD，仅用于此页面，不在报告中回显。
2. 在容器桌面的 Chromium 中访问 `https://vpn.sii.edu.cn`，按页面跳转进入 `https://cas.sii.edu.cn` 的正常登录流程。页面嵌在 noVNC 画布时依据当前截图操作，不能复用其他会话坐标。
3. 在实际 CAS 域名和登录表单确认后，使用用户已授权保存在本机的账号密码填写。需要读取时运行 `credentials.py read --reveal`，限制到此次认证上下文。不要把密码拼进启动命令、环境变量、自动化 URL、浏览器脚本文件或截图描述。
4. 初次没有保存且会话已提供并授权保存时，用 `credentials.py save --stdin` 从标准输入写入本机加密存储。无凭据则询问用户，不能从无关应用或账号中挖取。密码更改时更新同一存储。一次性验证码不保存。
5. 页面要求短信验证码时，按正常流程发送一次并向用户索取刚收到的验证码；不要自动反复发送，不复用旧验证码。需要扫码、系统授权或手动挑战时，遵循浏览器工具接管流程交给用户。使用工具规定的完成标记和标签管理规则。
6. 按当前适用规则处理协议确认：已有对该协议的明确授权时不重复询问；若工具或适用规则要求新确认，则引用具体要求并询问，不自行推断用户接受所有未来条款。
7. 完成后检查 aTrust 已连接，再跑 `status` 和 `verify`。需要平台网页登录时，在宿主机浏览器正常访问 `https://qz.sii.edu.cn/`，可能另需 CAS 会话或二次认证。不要把网络可达宣称为业务页面已登录。

本机容器中的原生 aTrust “Log In” 曾生成异常 CAS 参数；出现这类错误可改用容器 Chromium 的正常 VPN 门户登录，不构造或伪造 CAS ticket / service 参数。宿主机 `localhost:54631` 不是该容器的认证接口，不在宿主机启动 aTrust 去补救。

密码错误先核实当前表单、输入焦点及页面信息，最多做有依据的修正；连续失败应停止重复提交并询问用户，避免锁定账号。浏览器弹出“保存密码”默认不接受；本技能已经使用本机凭据存储。正常浏览器会话可随容器 `/root` 数据卷保留。

## 会话和平台限制

- 有效会话直接复用，日常启动不重建容器，不升级镜像。
- aTrust 可能明确提示长时间未访问应用而自动退出。本机已观察到该策略；启动时检测并正常重新登录，不默认添加后台保活或声称永久在线。
- 容器被重建、设备检查或服务端退出后可能要重新登录。使用正常认证，不伪造设备身份、不绕过 MFA。
- DPAPI 凭据绑定 Windows 用户 / 系统；复制技能 ZIP 不包含凭据，也不意味着另一台机器能解密。macOS 使用其本机钥匙串，可能弹出访问许可。
- `start` 脚本负责生命周期和探测，agent 按本文件完成浏览器登录；不能宣称该脚本本身已经处理所有网站认证或无人值守短信验证。
