# 常见问题与恢复

| 现象 | 先检查与处理 |
| --- | --- |
| `not_configured` | 运行 doctor，寻找已有 Compose / 容器，登记实际目录；不要立即创建重复部署。 |
| `docker_context_changed` | 核对当前和登记 context 指向的 daemon，尤其是否远程；确认本机目标后恢复登记或切换，不能盲目操作另一台主机。 |
| Docker 未就绪 | 启动现有引擎，检查初始化、WSL、虚拟化、系统权限和磁盘；不要自动清空 Docker 数据。 |
| 容器运行但启智不可达 | 检查可见 aTrust 状态、HTTP 代理、VPN 路由和防漏规则，区分未登录与代理问题。 |
| SOCKS 请求 TLS 失败 | 本部署使用已验证的 HTTP CONNECT 入口；不要因容器暴露了 SOCKS 就自动改用它。 |
| 网关解析成 198.18.x.x | 重新核实公网 DNS，更新认证入口真实地址和 fake-ip 排除；不要把 fake-IP 固化到 hosts。 |
| 容器 HTTP 可达，Clash 不通 | 检查实际 mode、优先规则、组选择、HTTP 节点端口、物理 interface-name 绑定和本地连接记录。 |
| 老浏览器标签连接关闭 | 重新打开平台主地址；不要重放过期 OAuth/OIDC code 或复制旧重定向 URL。 |
| 外网受影响 | 比较原基线、mode、组选择、规则和系统代理；恢复相关配置备份，不删除用户节点或数据卷。 |
| 重建后 aTrust 已退出 | 复用加密凭据执行正常认证；服务端策略要求的 MFA 仍需用户参与。 |
| 网页可用但 Inspire CLI 失败 | CLI token / 账号认证独立检查；VPN 通不代表 CLI token 有效。 |
| `connectivity_verified_needs_route_check` | 控制器不可用或连接太短未采集到；修复控制器读取或在客户端手动验证，不能将它当成完整通过。 |

仅读取必要的限量日志，去除 token、Cookie、密码、订阅 URL 后再输出。不要直接打印整个 `docker inspect` 环境变量、Clash YAML 或浏览器存储。API secret 仅在内存里构造本地控制器请求。

HTTP 403 可能是目标站点策略，不能直接断言 VPN 失败；结合 TLS 连通、代理链和其他目标判断，但不要把 403 页面当作成功访问业务。连接记录可能错过非常短的请求，有明确缺失时有针对性重试或查看客户端 UI；通过之后不反复扩大验证范围。

健康的日常启动不执行构建、升级、强制重建或故障注入。回滚只恢复本次更改的客户端扩展和模式；保留容器数据卷、用户其他代理、系统安装及原有业务任务。恢复后再次检查启智和两个外网站点。
